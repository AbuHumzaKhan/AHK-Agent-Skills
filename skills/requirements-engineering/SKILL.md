# AHK Requirements Engineering

## Sequence
Problem -> users -> goals -> scope -> functional requirements -> non-functional requirements -> data -> integrations -> edge cases -> acceptance criteria -> priorities -> dependencies.

## Requirements quality
Each requirement should be testable, unambiguous, necessary and traceable to a goal.

Use:
- user stories when appropriate
- acceptance criteria
- assumptions
- constraints
- dependencies
- out-of-scope items
- priority labels

Do not start implementation when material requirements remain ambiguous. Identify the smallest set of questions needed to resolve ambiguity.
