# AHK Testing QA

Define critical user journeys and acceptance criteria first.

Test:
- happy paths
- validation failures
- empty states
- boundary values
- permissions
- network/API failures
- duplicate submissions
- responsive layouts
- accessibility
- regression scenarios

For data work validate row counts, totals, joins, null behavior and KPI reconciliation.

For web work use appropriate unit, integration and E2E tests. Report what was tested, what passed, what failed and what remains unverified.
